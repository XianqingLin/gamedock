# GameDock：3D 场景描述

本文专门描述“GameDock”3D 据点的空间、视觉、物体、交互锚点与 AI 生成要求，是场景设计、灰盒制作和生成结果的验收依据。用户状态与接待顺序由[产品需求](./01-product-requirements.md)定义，具体工程实现由[技术实现要求](./02-technical-requirements.md)定义；本文不另行发明账号、游戏、成就或联机规则。

## 1. 场景定位与边界

### 1.1 核心定位

这是一座**温暖科技风的游戏收藏据点**。据点的结构和灯光偏未来，陈列与材质保留收藏馆的温度，不做成纯写实商店，也不做成堆满蓝紫霓虹和全息屏幕的通用科幻大厅。

场景承担三种长期体验：

- 玩家回到据点、接受接待并管理身份。
- 玩家浏览和选择游戏，随后进入独立游戏页面。
- 玩家在后续版本中回来查看成就与据点变化。

用户不是观看一张背景图，而是在具有真实通行关系的 3D 空间中自主移动。两种开场保持不变：

- 新用户站在关闭的店门外，自主开门、入店并前往环形前台。
- 已注册用户站在环形前台稍前方，直接面向门口侧服务员。

不设置从店外自动飞向店内的镜头，不设置把用户自动传送到前台的入店演出，也不要求已注册用户重复店外流程。

### 1.2 空间范围

据点由以下区域组成：

1. 店外入口与小范围门面。
2. 店门及入口缓冲区。
3. 中央环形前台、服务员与接待区域。
4. 环形前台内部的“存档核心”雕塑。
5. 环形前台左侧后方的游戏陈列区。
6. 环形前台右侧后方的成就展区。
7. 连接各区域的侧通道、墙体、门窗及其他边界。

不制作大型街区、复杂楼层、迷宫式仓库、额外后院或与当前布局无关的房间。当前只考虑桌面端自主移动，不生成手机虚拟摇杆或触摸控制界面。

### 1.3 功能边界

- 3D 据点是长期身份与内容展示区，不承载具体游戏联机过程。
- 不在据点内设置联机房间、匹配队列、好友邀请入口或虚构在线状态。游戏介绍与当前对局功能属于独立游戏页面及其固定外边框；好友邀请属于平台层（好友列表/通知），仅传递邀请信息，不在本文扩展。
- 游戏陈列区属于当前核心范围，由真实游戏数据驱动。
- 成就展区现在确定空间、结构和美术方向；成就数据、解锁规则、交互和展示逻辑属于后续功能，不因建好展区就视为已经完成。
- 环形前台为多服务员预留空间与锚点，但当前只启用门口侧接待服务员。未启用的位置不得出现假按钮、空对话或没有职责的人物。

## 2. 总体布局与空间基准

### 2.1 平面关系

入口、门口接待位和中心雕塑位于同一中轴线上。游戏与成就区域分别位于环形前台的左后、右后方，玩家沿前台两侧通道自然分流。

```text
                         据点后方

              游戏陈列区              成就展区
              （左后方）            （右后方）

       左侧通道                                  右侧通道

                    环形前台
              ┌───────────────┐
              │   “存档核心”   │
              │   雕塑与服务员 │
              └───────────────┘

                门口侧接待服务员
          已注册用户出生点 / 柜台交互点
                   入口缓冲区
                      店门
             新用户出生点（店外）
```

上图只表达左右、前后和功能关系，实际曲线与模块以以下灰盒基准为准。

### 2.2 坐标与默认尺寸

以下尺寸是默认灰盒基准，可以在灰盒验证后整体微调，但不得破坏入口、前台、左右分区和通行关系。

- 使用右手坐标系，`Y` 轴向上，地面为 `y = 0`，`1` 个场景单位按 `1` 米处理。
- 店门中心为 `(0, 0, 0)`，店外位于负 `Z` 方向，进入据点沿正 `Z` 方向；面对店内时，右侧为正 `X` 方向。
- 店内主体参考范围为宽 `14m`、深 `16m`、净高 `4.8m`，即 `x = -7m 至 7m`、`z = 0 至 16m`。
- 环形前台中心为 `(0, 0, 5.4m)`，外径约 `5.5m`、内径约 `3.9m`，柜台高度约 `1.05m`。
- 环形前台最靠近店门的外缘约为 `z = 2.65m`，因此入口到柜台保留约 `2.65m` 的缓冲空间。
- 中心雕塑总高约 `3.4m`，底座直径约 `1.4m`，位于环形前台中心。
- 左右主通道在货架、装饰和碰撞布置完成后的有效宽度不小于 `1.8m`，不能用装饰把通道压缩成只能侧身通过的缝隙。
- 地面保持连续，入口到前台不设置台阶、门槛高差或必须跳跃才能通过的障碍。
- 最终采用第一人称还是第三人称尚未确定；相机高度、近裁剪面和角色模型不得在上述建筑尺度之外另行写死一套相互矛盾的比例。

### 2.3 视线原则

- 新用户开门后，第一视觉焦点是门口侧服务员，第二视觉焦点是其后上方的中心雕塑。
- 已注册用户出生时，服务员面部和上半身应清楚可见，雕塑发光核心不得与人物面部重叠成一团高亮。
- 游戏陈列区和成就展区可以从门口或前台两侧辨认方向，但不需要在出生画面中完整展示全部内容。
- 中心雕塑、环形灯带和装饰屏幕不能亮过服务员、游戏封面和当前交互提示。
- 左右分区可以在视觉上呼应，但不能做成难以区分的镜像房间：左侧强调模块陈列，右侧强调墙面展示与收藏仪式感。

### 2.4 必需逻辑锚点

场景必须保留以下可命名、可定位的逻辑锚点。锚点是空间约定，不要求在最终画面中显示名称：

| 锚点 | 默认位置或区域 | 用途 |
| --- | --- | --- |
| `spawn.new` | `(0, 0, -2.2m)`，朝向正 `Z` | 新用户初始位置 |
| `spawn.returning` | `(0, 0, 1.9m)`，朝向正 `Z` | 已注册用户初始位置 |
| `door.entry` | `(0, 0, 0)` | 门交互、开关状态和通行控制 |
| `counter.center` | `(0, 0, 5.4m)` | 环形前台布局与模块生成基准 |
| `interaction.counter` | `(0, 0, 1.9m)`，位于柜台外侧 | 当前服务员接待与注册 |
| `npc.attendant` | 约 `(0, 0, 3.9m)`，朝向负 `Z` | 当前门口侧服务员 |
| `npc.service.02` 至 `npc.service.04` | 环形前台内部左、右、后侧预留站位 | 后续服务员扩展，当前不启用 |
| `sculpture.core` | `(0, 0, 5.4m)`，高度按雕塑结构设置 | “存档核心”雕塑与局部灯光 |
| `zone.games` | 环形前台左侧后方 | 游戏货架与游戏盒动态陈列 |
| `shelf.main` | `zone.games` 内的主陈列锚点 | 当前搜索与分类结果陈列 |
| `display.details` | 游戏陈列区内、靠近主通道 | 配合网页详情面板与游戏反馈 |
| `zone.achievements` | 环形前台右侧后方 | 后续成就墙与展示槽 |
| `boundary.walkable` | 店外小区域、入口、前台外侧及左右通道 | 移动边界与碰撞检查 |

所有出生点和交互点必须位于可行走区域，不得落在门扇、柜台、货架、雕塑、墙体或装饰物的碰撞体内。实际坐标集中配置；灰盒调整时统一更新锚点，不得在模型、对话和移动代码中分别维护不同坐标。

## 3. 店外入口与门面

### 3.1 门面设计

门面延续“科技收藏馆”的风格，以深石墨色框架、墨绿色金属板、少量深色木材和暖色招牌构成。玻璃只用于入口及必要展示，不采用整面高反射玻璃隐藏内部结构。

- 招牌保留“GameDock”，文字必须清晰、可校正，不使用 AI 随机生成的招牌字形。
- 门面可以有一条细窄暖色灯带勾勒入口，不使用大面积蓝紫霓虹、闪烁广告或虚构运营信息。
- 店外参考活动范围约为宽 `6m`、深 `4m`，只容纳出生、开门和小幅移动。
- 店外两侧用矮墙、绿化槽或与建筑一体的边界自然收束，不铺设引导玩家继续远离据点的长街。
- 可以保留少量雨景或湿润材质氛围，但不做高成本实时积水反射，也不能因此降低门框与地面的可见性。

### 3.2 新用户出生点

- `spawn.new` 正对店门，用户开始后无需大幅转动视角即可识别入口。
- 出生点不得紧贴门扇，也不得位于开门动画扫过的范围。
- 店外边界不得让新用户在尚未入店时跌落、绕到未完成区域或迷失。
- 新用户开始时店门处于关闭状态，不能默认敞开，也不能在场景加载完成后自动打开。

## 4. 店门与开关动画

### 4.1 结构与开启方式

- 默认采用单扇侧铰链平开门，净通行宽度约 `1.4m`、高度约 `2.6m`。
- 面对店内时，铰链位于左侧；门向店内开启，最大开启角约 `95°`，完全打开后门扇收向入口左侧，不占中央通道。
- 门框固定，门扇独立，门扇原点位于真实铰链位置，不能绕门扇中心或据点中心旋转。
- 门扇以深色金属框架和玻璃组成，保留清楚把手。玻璃反射不能强到让关闭的门看起来像开放通道。
- 开门路径不得扫过 `spawn.new`、`spawn.returning` 或门口侧交互区域，也不得在完全打开后堵住左侧主通道。

### 4.2 状态与交互

- 门至少具有关闭、打开中、打开、关闭中四种可区分状态，重复点击不得造成反向混乱、动画叠加或碰撞不同步。
- 用户在适当距离内可以主动打开或关闭门；交互入口必须可发现。
- 关闭状态下门不能直接被穿过。动画过程中和动画结束后的视觉位置、可通行状态与碰撞状态必须一致。
- 不自动播放完整入店镜头。门动画只改变门本身，不接管用户位置和视角。
- 减少动态效果模式下可以缩短或简化动画，但关闭门与打开门的可通行差异必须仍然清楚。
- 已注册用户出生在店内，门仍不得被场景默认为敞开；其接待流程不依赖先操作门。

## 5. 环形前台、服务员与中心雕塑

### 5.1 环形前台结构

- 环形前台是入口后的主要服务设施，外侧面向玩家，内侧容纳服务员与中心雕塑。
- 默认由 `12` 个标准化弧段组成完整圆环。渲染时可以合批，但资产逻辑上仍应允许替换单个弧段、调整材质和设置服务位。
- 柜台外径约 `5.5m`、内径约 `3.9m`，台面径向宽度约 `0.8m`、高度约 `1.05m`。
- 柜台内侧与雕塑底座之间保留约 `1.25m` 的径向活动空间，供当前及后续服务员站位，不把人物挤在雕塑和柜台之间。
- 柜台外圈不得封死左右通道。玩家从门口接待位两侧均可绕到后方功能区域。
- 柜台后侧可设计一个模块化可拆弧段作为员工通道的结构解释，但当前不向玩家开放，也不显示虚假的可通行提示。
- 门口侧柜台中央保持整洁，留给注册对话和未来确定的接待道具。终端、收纳与装饰放在侧面，不挡住服务员。

### 5.2 材质与造型

- 柜台主体使用墨绿色哑光面板、深石墨色底座和少量拉丝金属收边。
- 台面使用深色木材或具有温暖质感的哑光复合材料，与冷色金属形成对比。
- 柜台外侧可嵌入一圈低亮度暖色灯带，只用于勾勒形体，不做跑马灯和频繁变色。
- 结构以连续、干净的大曲面为主，减少无意义机械凸起、管线堆砌和容易藏住交互目标的复杂装饰。
- 当前接待位可以有小型实体终端或登记用品，但具体注册创意未确定，不把会员卡、印章或某种设备写成不可替换的既定方案。

### 5.3 服务员与扩展位

- 当前只启用 `npc.attendant`，位于环形前台内侧靠门方向，面向店门和 `spawn.returning`。
- 已注册用户出现时，服务员处于视野中心附近；用户与柜台保持自然对话距离，不需要贴近到穿模。
- 左、右、后侧最多预留三个额外标准服务位，与当前服务位合计形成四个结构扩展位。预留数量是空间默认值，不代表已经确定四名服务员或四种业务。
- 后续服务员必须有实际职责后再启用，不摆放无对话、无功能的人物填充圆环。
- 服务员使用原创或明确授权的人物形象，服装可以采用统一的深色制服、暖色滚边和小型据点标识，不使用现有游戏、动漫或影视角色。
- 人物风格保持精致、适度风格化，不追求复杂口型、面部捕捉或写实皮肤。当前只要求接待、注册对话和问候，复杂表演与自由聊天不属于默认要求。
- 人物不得穿模进入柜台或雕塑，也不得阻挡玩家外侧通道。

### 5.4 接待交互

- 新用户自主走到 `interaction.counter` 后，可以主动触发服务员对话并进入注册流程。
- 已注册用户在 `spawn.returning` 开始时直接进入简短问候，不需要从门外靠近，也不播放强制推镜。
- 对话与注册表单使用清晰的网页界面承载；场景提供人物、空间和交互上下文，不把关键文字烘焙进模型或纹理。
- 对话结束或注册成功后，用户留在当前柜台区域并恢复自主移动，不重置到另一个出生点。

### 5.5 中心雕塑：“存档核心”

中心装饰确定为原创雕塑“存档核心”，用于建立据点识别度，不承担联机、匹配或真实数据展示功能。

- 雕塑由圆形底座、三组开放式金属环和一个悬浮发光核心组成。
- 底座直径约 `1.4m`、高度约 `0.35m`，采用深色石材或哑光金属，造型稳重，不堆满细小零件。
- 金属环以不同倾角包围核心，形成有秩序的轨道感；环体保持足够通透，不形成遮挡服务员的实心球体。
- 核心使用抽象的像素晶体或切角多面体，不使用现成游戏标志、角色或品牌符号。
- 雕塑总高约 `3.4m`，发光核心位于主要服务员头部以上的视觉高度，避免人物面部与核心高光重叠。
- 核心以暖白和琥珀色为主，金属环边缘只保留少量青蓝色细光，不使用蓝紫渐变填满整个前台。
- 核心可以极缓慢旋转或浮动，环体不必全部运动；不得频闪、快速脉冲或持续喷射粒子。减少动态效果模式下保持静态。
- 雕塑默认是不可交互装饰，不显示“联机核心”“匹配中”等虚构状态，也不设置无功能点击入口。
- 后续如需让雕塑反映成就进展，只能在真实功能确定后增加表现，不在当前资源中烘焙虚构解锁状态。

## 6. 左右功能区域

### 6.1 左侧后方：游戏陈列区

游戏陈列区位于环形前台左侧后方，是玩家选择游戏的主要空间。整体感觉更接近秩序清楚的收藏档案馆，而不是密集堆货的商店仓库。

- 主货架沿左后墙布置，辅以一组低矮双面陈列架；高货架用于墙面，中央低货架高度原则上不超过 `1.3m`，避免遮挡空间视线。
- 货架采用深木色或暖灰背板、哑光金属框架和局部青蓝色细线，避免每层都使用高亮灯带。
- 从环形前台左侧通道进入后，玩家先看到主货架，再看到详情展示区，不需要穿过狭窄货架迷宫。
- 主货架与墙体、低货架之间保留连续通道，有效宽度不小于 `1.8m`。
- 货架、分类标牌和游戏盒采用统一模块生成，不把某一款游戏的位置、封面、模型或镜头写死在资产中。
- 游戏盒规格统一，正面封面、书脊名称和强调色来自游戏数据。默认陈列不能通过更大模型、专属展台或特殊灯光推荐某一款游戏。
- 同屏游戏数量受到统一分组、分页或分类规则控制；增加游戏时不得通过无限延长货架或扩大据点解决。
- 游戏详情主要由网页面板呈现，3D 书脊和标牌不是阅读详情的唯一途径。
- 选中反馈以轻微抽盒、高亮或简短放置动作为主，不要求用户跟随强制镜头移动。
- 游戏区照明以中性暖白为主，保证封面和名称可读；青蓝色只用于结构点缀，不给所有封面染上相同颜色。

### 6.2 右侧后方：成就展区

成就展区位于环形前台右侧后方，与游戏区形成功能对照：左侧是当前可以选择的内容，右侧是玩家长期留下的记录。

- 展区以完整墙面展示为主，采用模块化展示槽、徽章框架、浮雕背板和暖色射灯，营造收藏展厅而非排行榜竞技墙的感觉。
- 墙面可分为上、中、下三层展示带，中层作为主要视觉区域，上层用于大型标志或后续特殊展示，下层避免被近处装饰遮挡。
- 展示槽使用统一尺寸和稳定锚点，后续可以按成就数据替换内容，不为单个成就永久写死模型位置。
- 材质以暖灰、深色木材和哑光金属为主，少量金色用于边框，不让整个区域变成高反射金色墙。
- 成就墙可以保留一个中央据点徽记或抽象浮雕，作为未接入功能时也完整成立的美术构图。
- 当前成就系统未接入时，不展示虚构徽章、伪造解锁进度、假排行榜或可点击但无结果的槽位。未启用的数据槽以统一装饰盖板隐藏，不呈现为破损或空白灰块。
- 后续成就图标、名称、进度和解锁状态由数据驱动，不能直接烘焙进 AI 生成的墙面纹理。
- 锁定、解锁和其他状态后续不得只通过颜色区分；当前不提前定义具体成就交互。
- 右侧通道和成就墙前保留驻足空间，不能让玩家必须站到墙体贴面或环形柜台上才能观看。

## 7. 移动、碰撞与边界

### 7.1 主要路线

- 新用户路线为：店外出生点 → 打开店门 → 入口缓冲区 → 门口侧环形前台。
- 已注册用户路线直接从柜台前接待开始，对话后可选择左侧游戏区或右侧成就展区。
- 前台两侧主通道均连接后方区域，不要求玩家必须穿过柜台内部或绕过整面后墙。
- 店外出生点、入口、前台和游戏陈列区之间必须连通，用户能够仅通过常规移动完成当前核心流程。
- 可行走地面与不可行走区域应在视觉上可辨认；墙体、柜台、雕塑和货架的视觉边界应与碰撞边界基本一致。
- 不要求跳跃、蹲伏、攀爬、飞行或复杂物理模拟，不通过这些能力扩大场景范围。

### 7.2 碰撞层级

必须具备可靠碰撞的对象：

- 店外与店内边界、地面、墙体和固定门窗框架。
- 店门及其随开关状态变化的通行区域。
- 环形柜台、服务员、中心雕塑底座和主货架。
- 会明显阻挡路线的大型家具、展示墙或设备。

环形柜台使用少量弧段或简化碰撞体组合，不使用高面数台面模型直接进行逐三角碰撞。雕塑金属细环不必逐根碰撞，但底座与玩家人员可接触部分必须可靠，防止玩家进入雕塑实体。

小型装饰可以采用简化碰撞或置于行走路径之外。游戏盒的交互射线检测与场景移动碰撞分开处理，避免大量小物件同时参与两套计算。

### 7.3 视角与恢复

- 场景不能以固定机位串联代替自主移动，也不能强制用户沿轨道行进入店。
- 视角转动不得使用户看到未完成的场景外部、模型背面空洞或光照未覆盖区域；必要时应通过空间边界和场景封闭处理。
- 应提供恢复位置或解除卡住的方法。恢复应优先回到最近安全位置或对应柜台区域，不得改变用户注册状态，也不得清空游戏浏览状态。
- 具体移动按键、鼠标控制和第一/第三人称方案待定，但所有通道和交互区都必须保留合理操作空间。

## 8. 材质、灯光与整体风格

### 8.1 色彩基准

以下颜色作为材质与灯光方向参考，不要求所有物体使用完全相同的纯色：

- 深石墨色 `#1D2528`：建筑底座、门框、金属结构。
- 墨绿色 `#173F3A`：环形前台和部分墙面主体。
- 深木色 `#4A3528`：柜台台面、货架和收藏展示元素。
- 暖琥珀色 `#E8B86D`：招牌、雕塑核心和重点照明。
- 青蓝色 `#6FC7D4`：少量科技线条和局部设备点缀。
- 暖白色 `#F2E8D8`：主要阅读照明与必要文字。

不使用大面积蓝紫渐变、满墙霓虹或高饱和彩色灯带作为风格主体。

### 8.2 材质与地面

- 金属以哑光或拉丝质感为主，玻璃只保留必要反射，木材用于增加收藏与居住的温暖感。
- 地面采用深色细颗粒水磨石、哑光复合材质或局部金属嵌条，避免大面积镜面地板。
- 墙面由大块暖灰板、墨绿色面板和少量木质格栅组成，减少无意义机械纹理和密集凹凸。
- 游戏盒、服务员制服、柜台、货架和成就框架应具有可区分的粗糙度与材质，不共用一种塑料质感。

### 8.3 灯光层级

- 整体采用柔和暖色基础照明，入口和主要通道保持足够亮度，不能依赖纯黑隐藏未完成空间。
- 门口侧服务员有独立但柔和的面光，保证人物从门外和柜台前都看得清楚。
- 中心雕塑上方可以设置简洁环形顶灯，与地面圆环形成呼应；顶灯和雕塑不叠加成过曝光斑。
- 游戏区使用中性暖白阅读照明，成就区使用较集中的暖色展示照明，两者都比中心雕塑更克制。
- 避免过强泛光、浓雾、明显镜头光晕、频繁动态光源和高成本实时反射。
- 灯光必须覆盖用户实际可行走路线，不能只从某个固定总览角度看起来正确。

## 9. AI 场景生成与资源交付要求

### 9.1 可集成、可编辑的交付结果

AI 可用于概念设计、模型、材质、纹理或场景配置生成，但最终交付必须是可集成、可编辑的真实 3D 场景或资源，不能只交付概念图、视频、全景图或不可拆分的渲染结果。

生成结果至少区分：

- 固定建筑、门面、地面与边界。
- 独立门扇、门框和真实门轴。
- 可模块化替换的环形柜台弧段。
- 服务员模型与当前、预留站位锚点。
- 独立的雕塑底座、金属环、核心和灯光。
- 可复用货架、通用游戏盒与详情展示锚点。
- 成就墙、展示槽、盖板和后续动态内容锚点。
- 简化的移动碰撞与可行走边界。
- 本地材质、纹理及必要灯光配置。

### 9.2 资产结构与命名

- 使用本文坐标、尺度和朝向作为默认基准；需要调整时统一修改灰盒与锚点配置，不能逐个模型随意缩放拼装。
- 门扇、柜台弧段、服务员、雕塑、货架和成就展示槽必须可独立访问，不能全部合并成单一网格。
- 环形柜台的视觉曲线可以平滑，碰撞仍采用少量简单弧段，不为细碎装饰创建复杂碰撞。
- 雕塑核心、金属环和底座分层，方便控制动画、减少动态效果和资源替换。
- 成就展示内容不得与墙体合并；游戏封面不得与游戏盒模型永久合并。
- 必需锚点使用稳定名称，重生成模型后保持锚点语义，而不是让业务代码适配每次随机坐标。
- 几何体法线、原点、旋转轴和层级关系必须正确，不得出现反面、闪烁、重叠面或围绕错误轴心运动。
- 碰撞代理与渲染模型分离，优先使用简单、稳定的形状。

### 9.3 生成风格约束

- 优先生成清楚的大形体、连续曲面、模块化陈列和少量标志性细节，避免 AI 常见的无意义机械纹理、随机管线、过密按钮和伪文字。
- 科技感主要来自环形结构、中心雕塑、材质对比和有序灯光，不来自在每个表面增加发光线条与全息屏。
- 保持游戏区、成就区和服务区各自的功能辨识度，不生成大量没有用途的门、终端、屏幕和通道。
- 服务员、雕塑、据点徽记和装饰图案必须原创或有明确授权，不使用现有游戏角色、品牌标志或来源不明素材。
- 招牌和功能文字使用可控制、可校正的文本或纹理，不接受乱码作为最终界面。

### 9.4 内容与资源约束

- 所有 AI 生成或辅助生成的角色、模型、招牌、纹理和材质都必须记录来源与生成方式，并检查第三方知识产权和可用许可。
- 正式资源本地化并按需加载，不依赖生成服务在每次打开网页时重新生成场景。
- 不把测试游戏、虚构在线人数、联机状态、注册成功状态、具体注册方案或虚构的成就烘焙进资源。
- 资源体积、纹理尺寸、面数、透明材质、阴影和后处理必须受控；量化预算确定前，不能以“AI 生成”作为豁免性能要求的理由。

## 10. 场景验收

1. 新用户出现在 `spawn.new`，正对关闭店门；已注册用户出现在 `spawn.returning`，面向环形前台内侧的当前服务员。
2. 店门具有清楚的打开和关闭动画，门轴、开门方向、碰撞与通行状态正确，两个出生点均不在门扇运动范围内。
3. 入口、门口接待位与“存档核心”位于同一中轴，开门后能明确看到服务员，没有强制入店镜头或自动传送。
4. 环形前台位于店门正后方，左右均保留有效宽度不小于 `1.8m` 的通道，玩家不会在进入后被圆环封死。
5. 当前只启用门口侧服务员；其他服务位只有空间和锚点预留，不存在无功能人物或虚假交互。
6. 中心雕塑位于圆环内部，结构完整、材质与灯光克制，不遮挡服务员面部，不显示虚构联机或成就状态。
7. 游戏陈列区位于环形前台左侧后方，货架和游戏盒由统一数据规则生成，没有单款游戏专属展示。
8. 成就展区位于环形前台右侧后方，墙体与展示槽可独立编辑；未接入成就功能时不展示虚构内容或无效按钮。
9. 用户不能穿过墙体、关闭的门、环形柜台、服务员、雕塑底座或主货架，也不能从边界跌落或进入未完成区域。
10. 从门外、柜台前、左右通道和后方区域观察时，场景均无大面积缺失、明显穿模、错误材质、乱码文字或过暗交互目标。
11. 游戏封面与服务员清晰可读，雕塑、灯带、玻璃反射和后处理不会压过主要交互目标。
12. 场景不包含联机房间、匹配队列、好友邀请入口或虚构在线状态；好友邀请由平台层承载（仅传递信息），具体联机由各游戏自理。
13. AI 生成结果具有可编辑模块、稳定锚点、独立门扇、独立雕塑与展示槽、必要碰撞和本地资源，不以概念图或静态背景代替可交互 3D 据点。

## 11. 后续确认与扩展项

以下内容不影响当前布局定稿，但在对应功能实施前仍需确认：

- 第一人称或第三人称视角、对应相机参数、移动按键和指针锁定方案。
- 服务员的最终形象、具体数量、实际职责和是否需要简单待机动画。
- 创意注册的最终形式，以及它需要使用的柜台道具。
- 成就的数据来源、解锁规则、展示槽数量、动态内容和交互方式。
- 独立游戏页面固定外边框的具体布局、游戏嵌入方式及好友邀请能力。
- AI 生成工具、最终资源格式、许可记录方式和量化性能预算。

未确认的功能不得通过假按钮、虚构数据或无职责人物提前伪装完成。当前可以先按本文尺寸制作灰盒，验证出生点、门、环形前台、左右通道和中心雕塑，再进入最终美术资源制作。
