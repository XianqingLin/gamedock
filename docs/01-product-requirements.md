# GameDock：产品需求

本文是产品业务与用户行为的唯一需求来源，不包含代码实现、技术选型或测试实现。技术约束见[技术实现要求](./02-technical-requirements.md)，进度与决策追溯见[开发日志](./devlog.md)。

> 2026-11 修订：界面形态确定为功能完整的列表模式；最初的"3D 据点收藏馆"概念已从当前需求中移除。如未来重启 3D 方向，将另立文档，不在本文预留章节或验收项。

## 1. 产品定位与范围

GameDock 是一个网页游戏导航、浏览与启动平台（个人学习项目）。平台提供游戏库浏览、账号体系与基础社交能力；游戏以独立游戏页面 + 平台外边框的形式运行。**平台层不做联机**：不提供大厅、房间、匹配、排位、对战中转、对战凭证或聊天室，各游戏能否联机、怎么联机是游戏自己的事。唯一例外是好友邀请（仅信息传递）。

当前版本面向桌面端，交付范围：

- 游戏库浏览：封面网格浏览、搜索、分类筛选、游戏详情与启动。
- 账号体系：用户名密码注册与登录、会话保持、个人主页。
- 好友社交：发送/接受/拒绝/取消好友请求、删除好友、好友列表（首版无在线状态）。
- 平台存档：各游戏的存档读写，按游戏隔离，值对平台不透明。
- 游戏托管与启动：游戏静态资源托管在独立内容域（跨源 iframe 运行，与平台会话隔离）。

当前版本不包含：

- 手机端适配、触摸操作或针对手机浏览器的验收。
- 3D 场景（已从当前范围移除，重启另立文档）。
- 具体游戏的内部玩法与联机服务器（各游戏联机自理）。
- 支付、广告、论坛、评论、积分、成就、排行榜或独立聊天室。
- 游戏投稿与审核流程（等真实需求出现再建；存储布局已预留）。

好友邀请是平台层唯一的联机相关能力：负责邀请的发出与展示、点击后把人带进游戏页面并传递游戏自定义的连接参数、提供可验证的身份凭证；连接建立与数据传输完全归游戏。该能力当前尚未实现，接入时另行补充需求。

游戏启动地址与元数据来自平台的游戏数据；《死神 VS 火影》重构版仅作为第一款接入的游戏，不享有特殊样式、推荐位、额外文案或特殊交互。演示数据只用于开发和测试，不作为已正式接入的游戏发布。

## 2. 内容与展示原则

### 2.1 平等展示

- 所有游戏使用相同的卡片规格、信息层级、操作方式和默认视觉权重。
- 陈列顺序只由统一的数据排序规则决定，不设置推荐、热度或付费权重。
- 悬停、聚焦和选中时允许出现临时高亮，这不视为特殊推荐。
- 所有游戏均可查看详情；不可用游戏仅限制启动，不限制信息浏览。

### 2.2 文案与信息

- 页面只保留品牌名称与完成任务所需的功能性文字。
- 不使用"镇店游戏""必玩神作"等推荐性措辞；避免商业化、商城化的用语，保持工具性、社区化的表达。
- 游戏介绍、版本等信息只能来自数据；缺失时隐藏整个字段，不显示空标签或编造内容。
- 没有真实数据来源时不显示在线人数。
- 错误和空状态只说明当前状态及可执行操作，不使用宣传性文案。

### 2.3 视觉方向

- 深色平台界面：整体克制统一，以内容为主角，不堆砌装饰与动效。
- 品牌色用于重点强调，其余状态色仅作功能性区分；避免大面积高饱和撞色。
- 装饰不得比主要交互目标更醒目；不设置无实际功能的可点击假象、虚假按钮或空页面入口。
- 不使用来源不明、未经授权或侵权的角色、海报、商标和美术资源。

## 3. 账号与好友

### 3.1 账号

- 注册与登录使用用户名 + 密码；用户名重复、格式非法或密码过短时给出明确错误。
- 登录状态通过 httpOnly Cookie 会话保持；Cookie 不进入游戏内容域。
- 登出清除会话；会话过期后按未登录处理，不误用旧身份。
- 未登录可以浏览游戏库与详情；好友与存档需要登录。
- 个人主页展示账号信息与好友列表。

### 3.2 好友

- 支持发送好友请求、接受、拒绝、取消请求和删除好友。
- 好友列表展示互为好友的用户。
- 重复请求、对自己发请求、非好友操作等无效操作返回明确错误，不产生重复数据。

### 3.3 平台存档

- 每款游戏按 slug 隔离，存档键值由游戏自定义，值对平台不透明。
- 需要登录；未接入平台的 slug 返回明确错误。
- 单个存档值有大小上限，超限返回明确错误。

## 4. 浏览、详情与启动

### 4.1 首页与默认状态

首页包含品牌名、搜索、分类筛选、游戏卡片列表和明确的"开始游戏"入口。

- 列表模式是唯一浏览界面（不再有场景/列表切换）。
- 默认不自动选中游戏，不自动打开游戏详情。
- 未选择游戏时不显示游戏详情和启动按钮。

### 4.2 搜索与分类

- 首版搜索只匹配游戏名称，不扩展到分类、简介、拼音或模糊搜索。
- 搜索忽略关键词首尾空白和英文字母大小写，采用名称包含匹配。
- 分类为单选，包含"全部"和一个具体分类；游戏属于多个分类时，归入其任一已配置分类。
- 搜索与分类组合时，结果必须同时满足两个条件。
- 游戏按数据配置顺序稳定陈列，搜索和筛选不改变其相对顺序。
- 无搜索结果时显示功能性空状态，并提供"清除筛选"；该操作清空搜索关键词、将分类恢复为"全部"。
- 当前选中的游戏被筛选排除时，清除选中状态并关闭详情，不自动选中首个结果。

### 4.3 选择、详情与导航

- 选择游戏后，同步更新选中状态、详情和可分享的详情 URL。
- 刷新详情 URL 后恢复对应游戏；游戏标识不存在时显示未找到状态。
- 详情显示封面、名称、分类和可用状态，以及数据中实际存在且含义明确的其他信息；字段含义或来源未确认时不展示。
- 关闭按钮与 `Escape` 均退出详情并返回浏览视图，保留当前搜索和分类。直接打开详情 URL 时，关闭后返回首页。
- 浏览器前进、后退按访问历史恢复页面、详情和选中状态。
- 再次选择其他游戏时，上一个卡片恢复普通状态，详情直接更新，不重复播放冗长动画。

### 4.4 游戏启动

启动入口的可用性按以下规则确定：

- 状态为"可用"且具有有效启动地址：显示可用的"开始游戏"按钮。
- 状态为"未开放"：显示"未开放"，禁用启动按钮。
- 状态为"维护中"：显示"维护中"，禁用启动按钮。
- 状态为"可用"但启动地址缺失或无效：显示"暂不可启动"，禁用启动按钮。
- 游戏不存在：显示未找到状态，不提供启动入口。

启动必须由用户主动点击触发，不得进入空白页面。站内游戏经 `/play/:slug` 运行页加载；外链只接受 `http:` 和 `https:` 协议，新窗口打开时设置 `noopener`、`noreferrer`。

### 4.5 游戏运行页

- 运行页 = 平台外边框（返回、标题、登录区、全屏）+ 游戏 iframe；游戏逻辑全部在 iframe 内。
- 游戏 iframe 与平台跨源（独立内容域）：平台会话 Cookie 不进入游戏域，游戏无法读取平台页面数据。
- 平台与游戏之间通过 postMessage 窄接口通信：加载完成后平台下发握手消息（携带游戏 slug 与当前登录用户或 null）；消息信封带版本号，游戏消息以 `game:` 开头、平台消息以 `platform:` 开头。
- 登录态确认前不挂 iframe，避免游戏拿到不完整的用户状态。
- 后续存档、分数上报、联机凭证下发都在这条通道上扩展，游戏不直接操作平台内部状态。

## 5. 桌面端与可访问性

### 5.1 当前设备边界

- 当前版本只针对桌面浏览器进行布局、交互和验收，不要求手机端布局或触摸操作。
- 页面缩放至 200% 或文字换行后，主要按钮和导航仍应可见、可操作。

### 5.2 键盘与辅助功能

- 支持 `Tab` 导航、`Enter` 激活和 `Escape` 退出详情、关闭弹层；存在多个状态时应按明确的优先级逐层退出。
- 使用清晰的焦点样式、语义化控件和必要的无障碍名称。
- 模态弹层打开后将焦点移入其中并限制焦点范围，关闭后恢复到原入口。
- 普通文字与背景对比度至少为 4.5:1，大号文字至少为 3:1。
- 不仅通过颜色表达选中、维护中、未开放或其他状态。
- DOM 点击目标尺寸至少为 44×44 CSS 像素。

## 6. 可选声音

声音不是当前版本必做功能，不得阻塞核心流程。实现声音时必须满足：

- 首次使用默认静音，只能由用户主动开启，不自动播放音乐。
- 提供明确的声音开关，并在本地保存用户偏好；恢复偏好时仍不得违反浏览器自动播放限制。
- 只使用低音量、克制的音效，不播放突然或高音量声音。
- 页面不可见时暂停非必要音频。
- 音频加载或播放失败不影响浏览、详情和启动，也不产生持续错误提示。

## 7. 异常与降级

- 身份状态或注册请求失败时，不得误用已登录身份；应提供重试或其他明确的恢复方式。
- 游戏数据为空与搜索无结果应显示不同状态；前者不提供"清除筛选"作为解决手段。
- 游戏不存在和普通路由未找到分别提供明确的未找到状态及返回浏览入口。
- 封面缺失或加载失败时使用统一的本地默认封面，不出现破图、空白灰块或随机外链占位图。
- 单个封面或资源失败不应导致整个应用不可用。
- 游戏未开放、维护中或启动地址异常时，按第 4.4 节处理，不显示可点击的无效启动按钮。
- 游戏内容域静态资源加载失败时显示明确的加载失败状态，不影响平台其他页面。

## 8. 产品验收标准

1. 用户可完成注册、登录、登出、会话保持与个人主页查看；无效凭据与重复注册被明确拒绝。
2. 好友请求的发送、接受、拒绝、取消与删除行为正确，无效操作有明确错误且不产生重复数据。
3. 平台存档按登录用户与游戏 slug 隔离，写读列删行为正确，未接入 slug 返回明确错误。
4. 用户可完成搜索、组合筛选、选择、详情查看与启动。
5. 默认不自动选中游戏；筛选排除选中游戏后的行为符合第 4.2 节。
6. 每款游戏使用统一的展示和交互规则，第一款游戏没有任何特殊展示。
7. 详情 URL 可分享、刷新恢复，非法游戏地址和普通非法路由均有明确状态。
8. 可用、维护中、未开放及启动地址异常的游戏具有正确且不可混淆的按钮状态。
9. 游戏在跨源 iframe 中运行；握手携带 slug 与登录用户；平台外边框的返回与全屏可用。
10. 主域不再直接托管游戏静态资源：`/g/*` 重定向到内容域；游戏域不承载平台页面与会话 Cookie。
11. 桌面端键盘、焦点和 200% 缩放行为符合本文要求，不以手机端适配作为当前验收条件。
12. 页面没有宣传性文案、虚构数据、破图、空白占位、伪造在线人数或无实际作用的按钮。
