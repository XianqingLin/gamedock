# 小林游戏铺：产品需求

本文是产品业务与用户行为的唯一需求来源，不包含代码实现、技术选型或测试实现。场景空间、物体关系与场景生成约束见[3D 场景描述](./04-scene-description.md)，技术约束见[技术实现要求](./02-technical-requirements.md)，本轮修订及默认决策见[业务评审记录](./03-business-review.md)。

## 1. 产品定位与范围

小林游戏铺（XiaoLin Game Shop）是一个网页游戏导航、浏览与启动平台。当前主要界面是一座可自主移动、可交互的 3D 科技收藏馆式玩家据点，每款游戏以货架上的光盘收藏盒呈现。用户可以搜索、筛选、查看详情并启动游戏，也可以切换到功能完整的列表模式。

当前版本面向桌面端，首版交付范围：

- 桌面端网页应用与可自主移动的 3D 据点。
- 新用户与已注册用户识别，以及由用户状态决定的初始位置与接待流程。
- 可开关的据点大门、环形前台服务员、新用户注册和已注册用户问候。
- 由游戏数据动态生成的游戏盒与货架陈列。
- 搜索、分类筛选、游戏选择、详情和启动入口。
- 与 3D 场景共享状态且可独立使用的桌面列表模式。
- 加载、空数据、无搜索结果、游戏不可用、资源失败和 3D 不可用时的必要状态。
- 桌面端键盘操作、减少动态效果和基础可访问性支持。

当前版本不包含：

- 手机端适配、触摸移动控制或针对手机浏览器的验收。
- 面向手机端和低性能设备的独立 2D 网站；该网站作为后续单独交付范围。
- 具体游戏的内部玩法、游戏联机服务器或平台级联机房间。
- 支付、广告、论坛、评论、积分、成就、排行榜或独立聊天室。
- 与上述核心流程无关的后端系统。

成就展区的空间和美术结构可以按场景描述预留，但成就数据、解锁规则和交互不属于当前交付范围。具体联机、游戏介绍与好友邀请属于独立游戏页面及其外边框，不在 3D 据点内设置对应设施。

游戏启动地址、真实在线人数和运行数据由配置或后续服务提供。《死神 vs 火影》重构版仅作为第一款接入的游戏数据，不享有专属区域、特殊镜头、推荐位、独特样式、额外文案或特殊交互。演示数据只用于开发和测试，不作为已正式接入的游戏发布。

## 2. 内容与展示原则

### 2.1 平等展示

- 所有游戏使用相同的游戏盒规格、信息层级、操作方式和默认视觉权重。
- 陈列顺序只由统一的数据排序规则决定，不设置推荐、热度或付费权重。
- 悬停、聚焦和选中时允许出现临时高亮或抽盒反馈，这不视为特殊推荐。
- 所有游戏均可查看详情；不可用游戏仅限制启动，不限制信息浏览。

### 2.2 文案与信息

- 页面只保留品牌名称、服务员接待与注册所需文案，以及完成任务所需的功能性文字。
- 服务员可以向已注册用户打招呼，但不得借此添加品牌标语、宣传口号、虚构运营公告或营销推荐。
- 不使用“镇店游戏”“必玩神作”“童年神作”等推荐性措辞。
- 游戏介绍、版本、更新时间和在线人数等信息只能来自数据；缺失时隐藏整个字段，不显示空标签或编造内容。
- 没有真实数据来源时不显示在线人数。
- 错误和空状态只说明当前状态及可执行操作，不使用宣传性文案。

### 2.3 视觉方向

- 主题为温暖科技风的游戏收藏据点：空间结构和灯光偏未来，陈列与材质保留收藏馆的温度。
- 不做成纯写实商店，也不做成堆满蓝紫霓虹、全息屏幕和无意义机械细节的通用科幻大厅。
- 主色为深石墨色、墨绿色和深木色，暖琥珀色用于重点照明，青蓝色只作少量科技点缀。
- 主要材质包括哑光金属、深色木材、暖灰复合板、玻璃和塑料光盘盒，避免所有物体呈现同一种塑料质感。
- 以柔和暖色基础照明为主，游戏陈列区偏中性暖白，成就展区采用克制的展示照明；避免过度泛光、过曝、浓雾、强烈镜头光晕和大面积纯黑区域。
- 主要场景元素包括环形前台、原创“存档核心”雕塑、模块化游戏陈列架和右侧成就展区，具体布局以场景描述为准。
- 装饰不得遮挡游戏、服务员或行走路径，也不得比主要交互目标更醒目；不设置无实际功能的可点击假象、虚假按钮或空页面入口。
- 不使用来源不明、未经授权或侵权的角色、海报、商标和美术资源。AI 生成资源同样必须满足这一要求。

## 3. 入店、接待与注册

### 3.1 用户状态与初始位置

- 场景首次加载时，根据当前可验证的注册状态区分新用户和已注册用户，并以此设置初始位置；两种状态不得使用同一个默认出生点代替。
- 新用户的初始位置在店门外，视角朝向店铺入口。
- 已注册用户的初始位置在前台稍前方，视角面向服务员，不需要从店外走入。
- 具体空间锚点、朝向、距离和防碰撞要求见[3D 场景描述](./04-scene-description.md)。
- 同一次页面访问中的模式切换或场景恢复不得无故重置用户位置，也不得重复执行已经完成的接待流程。

### 3.2 新用户入店

- 店铺大门不再默认敞开。新用户开始时不穿透关闭的大门，门必须提供可辨认的打开与关闭动画。
- 新用户通过自主移动和门交互完成入店，不播放强制入店动画，不自动把用户或镜头从门外移动到前台。
- 新用户进入店内后，可自主走到前台并与服务员交互，进入注册对话。
- 注册是当前新用户接待流程的第一步。未完成注册时，不得把用户标记为已注册用户或进入已注册用户的接待状态。

### 3.3 创意注册

- 注册应融入服务员与柜台情境，具有明确的情境化和创意表现，而不是与场景毫无关联的通用弹窗。
- 具体创意形式、注册字段和身份服务尚未确定，实施前必须另行确认，不得仅凭“有创意”扩大账号功能。
- 输入、校验、错误提示和提交操作必须使用清晰可操作的网页控件，不依赖难以阅读的 3D 小字或仅能点击画布完成的表单。
- 注册成功后，将当前用户视为已注册用户，结束注册对话并把移动控制权交还用户；不得通过重新加载页面把用户强行移回门外。
- 注册失败或身份服务不可用时，应说明状态并保留可执行的恢复入口，不得伪装注册成功。

### 3.4 已注册用户接待

- 已注册用户直接出现在前台稍前方并面向服务员，由服务员打招呼后结束接待对话。
- 该流程不包含强制镜头移动，也不要求已注册用户先操作店门。
- 对话结束后，用户可自主移动并继续浏览游戏。

## 4. 浏览、详情与启动

### 4.1 首页与默认状态

首页包含中英文品牌名、搜索、分类筛选、场景/列表切换、主内容区、选中游戏的详情和明确的“开始游戏”按钮。仅在实现声音功能时显示声音开关。

- 桌面端首次进入默认使用场景模式；3D 不可用时直接使用列表模式。
- 用户手动切换模式后，本次页面访问期间不再自动覆盖其选择；刷新后按上述默认规则重新判断。
- 默认不自动选中游戏，不自动打开游戏详情，不强制播放店铺介绍动画或展示店铺介绍弹窗。
- 未选择游戏时不显示游戏详情和启动按钮。

### 4.2 搜索与分类

- 首版搜索只匹配游戏名称，不扩展到分类、简介、拼音或模糊搜索。
- 搜索忽略关键词首尾空白和英文字母大小写，采用名称包含匹配。
- 分类为单选，包含“全部”和一个具体分类；游戏属于多个分类时，归入其任一已配置分类。
- 搜索与分类组合时，结果必须同时满足两个条件。
- 游戏按数据配置顺序稳定陈列，搜索和筛选不改变其相对顺序。
- 无搜索结果时显示功能性空状态，并提供“清除筛选”；该操作清空搜索关键词、将分类恢复为“全部”，不改变场景或列表模式。
- 当前选中的游戏被筛选排除时，清除选中状态并关闭详情，不自动选中首个结果。

### 4.3 选择、详情与导航

- 选择游戏后，同步更新游戏盒状态、详情和可分享的详情 URL；场景与列表中的选中状态保持一致。
- 刷新详情 URL 后恢复对应游戏；游戏标识不存在时显示未找到状态。
- 详情显示封面、名称、分类和可用状态，以及数据中实际存在且含义明确的其他信息；字段含义或来源未确认时不展示。
- 详情可以采用独立页面或支持路由的面板，但两种形式必须具有一致的信息和操作。
- 关闭按钮与 `Escape` 均退出详情并返回浏览视图，保留当前搜索、分类和显示模式。直接打开详情 URL 时，关闭后返回首页。
- 浏览器前进、后退按访问历史恢复页面、详情和选中状态，不要求与关闭按钮产生完全相同的历史记录。
- 再次选择其他游戏时，上一个游戏盒恢复普通状态，详情直接更新，不重复播放冗长动画。

### 4.4 游戏启动

启动入口的可用性按以下规则确定：

- 状态为“可用”且具有有效启动地址：显示可用的“开始游戏”按钮。
- 状态为“未开放”：显示“未开放”，禁用启动按钮。
- 状态为“维护中”：显示“维护中”，禁用启动按钮。
- 状态为“可用”但启动地址缺失或无效：显示“暂不可启动”，禁用启动按钮。
- 游戏不存在：显示未找到状态，不提供启动入口。

启动必须由用户主动点击触发，不得进入空白页面。平台首页不承载具体游戏逻辑，3D 场景失败不得影响列表中的详情查看与游戏启动。

### 4.5 列表模式

列表模式是当前桌面版的完整浏览界面，不是仅用于降级的纯文本页，也不等同于后续独立的 2D 网站：

- 与 3D 场景使用同一份游戏数据，并提供清晰的封面网格或紧凑列表。
- 支持搜索、分类、选择、查看详情和启动游戏。
- 与 3D 场景同步搜索、分类、选中游戏和不可用状态。
- 用户可随时主动切换；3D 不可用或加载失败时也可完成全部核心浏览与启动流程。
- 新用户遇到 3D 不可用时，仍须能通过等价的网页控件完成必要的注册流程，不得因画布失败而被永久拦截。

## 5. 3D 场景与交互

### 5.1 场景区域

场景控制在少量清晰区域内，不制作需要长时间探索的大型据点。空间布局与生成细节以[3D 场景描述](./04-scene-description.md)为准。

- 店外入口：提供新用户初始位置、据点门面和可开关的大门，不扩展为需要长时间行走的大型街区。
- 环形前台与服务员：位于门后中轴，承担新用户注册、已注册用户问候和接待对话。当前只启用门口侧服务员，其他位置仅为后续实际职责预留。
- 中心雕塑：环形前台内部设置原创“存档核心”，作为据点视觉锚点，不承担联机、匹配或虚构数据展示。
- 左侧游戏陈列区：位于环形前台左侧后方，陈列当前搜索结果和分类下的游戏盒。游戏较多时，通过统一的分组、分页或分类切换控制同屏数量，不为单款游戏写死位置或模型。
- 右侧成就展区：位于环形前台右侧后方，当前只建设空间与美术结构；成就数据和交互后续接入，未启用时不展示虚构内容或无效入口。
- 信息展示：选中游戏后，可使用简短抽盒或放置动画配合视觉反馈；详细内容以清晰的面板呈现，不依赖难以阅读的 3D 小字。

### 5.2 游戏盒

- 每款游戏采用统一光盘收藏盒设计。
- 正面显示封面，书脊显示名称。空间不足时可截断书脊文字，但详情和无障碍名称必须保留完整游戏名。
- 悬停或键盘聚焦对应入口时，提供轻微抽出或高亮反馈。
- 可交互目标使用明确的指针和焦点样式，并具有足够的点击区域。
- 选择后更新选中状态、详情和 URL；不得强制播放冗长镜头动画。不可用游戏也遵循相同的信息查看流程。
- 不使用难以识别的裸光盘，不为单款游戏设计独立交互规则。

### 5.3 自主移动与视角

- 当前桌面版以用户自主移动作为据点内主导航方式，不再以总览、货架、详情三个固定机位替代行走。
- 新用户入店和已注册用户接待均不依赖强制镜头移动；除明确的交互反馈外，用户保持对位置与视角的控制。
- 场景必须提供清晰的行走路径、边界与碰撞，避免穿墙、穿过柜台、雕塑或货架、跌落场景以及走出可玩区域。
- 必须提供可发现的恢复位置或解除卡住的方法，并保证恢复后不会错误改变用户注册状态、搜索条件或选中游戏。
- 具体移动按键、视角方案和指针锁定行为由技术实现确定，但不能阻断键盘访问页面控件，也不能把用户永久锁在画布中。

### 5.4 动画与动态效果

- 店门打开与关闭是明确保留的功能性动画；其他入店、接待过程不强制使用动画。
- 常规选中、悬停和界面切换动画不超过 300ms，且可以中断，不能拖慢连续浏览。店门动画不适用该 300ms 上限，但不得因重复触发造成状态或碰撞错误。
- 遵循系统的减少动态效果设置，跳过非必要镜头、抽盒、雕塑环境动效和界面动画；店门可改用更短或简化的状态反馈，但仍须清楚表达打开与关闭状态。
- 减少动态效果设置不强制用户改用列表模式。

## 6. 桌面端与可访问性

### 6.1 当前设备边界

- 当前版本只针对桌面浏览器进行布局、交互和验收，不要求手机端布局、触摸移动或小屏默认列表。
- 后续可单独开发常规 2D 网站，供手机端和低性能设备使用；该网站不属于当前版本必须完成的交付物。
- 当前桌面列表模式继续承担辅助浏览和 3D 故障降级，不因后续 2D 网站规划而取消。
- 页面缩放至 200% 或文字换行后，主要按钮和导航仍应可见、可操作。

### 6.2 键盘与辅助功能

- 所有 3D 游戏选择操作都有对应的页面控件，不将画布作为唯一操作入口。
- 支持 `Tab` 导航、`Enter` 激活和 `Escape` 退出详情、关闭弹层或释放画布输入；存在多个状态时应按明确的优先级逐层退出。
- 使用清晰的焦点样式、语义化控件和必要的无障碍名称。
- 模态弹层打开后将焦点移入其中并限制焦点范围，关闭后恢复到原入口。
- 普通文字与背景对比度至少为 4.5:1，大号文字至少为 3:1。
- 不仅通过颜色表达选中、维护中、未开放或其他状态。
- DOM 点击目标尺寸至少为 44×44 CSS 像素。

## 7. 可选声音

声音不是当前版本必做功能，不得阻塞核心流程。实现声音时必须满足：

- 首次使用默认静音，只能由用户主动开启，不自动播放音乐。
- 提供明确的声音开关，并在本地保存用户偏好；恢复偏好时仍不得违反浏览器自动播放限制。
- 只使用低音量的环境雨声、简短抽盒声和按钮声，不播放突然或高音量音效。
- 页面不可见时暂停非必要音频。
- 音频加载或播放失败不影响浏览、详情和启动，也不产生持续错误提示。

## 8. 异常与降级

- 3D 加载期间优先展示可操作的基础界面和轻量加载状态。
- WebGL 不可用、3D 初始化失败或关键场景资源加载失败时，自动切换至桌面列表模式并显示简短状态，不阻断必要的注册、详情和启动流程。
- 身份状态或注册请求失败时，不得误用已注册用户身份；应提供重试或其他明确的恢复方式。
- 游戏数据为空与搜索无结果应显示不同状态；前者不提供“清除筛选”作为解决手段。
- 游戏不存在和普通路由未找到分别提供明确的未找到状态及返回浏览入口。
- 封面缺失或加载失败时使用统一的本地默认封面，不出现破图、空白灰块或随机外链占位图。
- 单个装饰、封面或音频资源失败不应导致整个应用不可用。
- 游戏未开放、维护中或启动地址异常时，按第 4.4 节处理，不显示可点击的无效启动按钮。

## 9. 产品验收标准

1. 新用户从店门外开始，店门初始不敞开，能够通过门开关交互和自主移动入店，全程不被强制镜头动画带到前台。
2. 已注册用户从前台稍前方开始并面向服务员，完成简短问候后能够自主移动，不需要重复店外入店流程。
3. 新用户能在服务员接待情境中完成注册；注册成功后不错误重置到门外，失败时不会伪装成功。已注册用户不会被要求重复注册。
4. 用户可以在桌面 3D 场景中自主移动，店门、墙体、柜台和货架碰撞有效，并能从异常位置恢复。
5. 用户可在场景和列表中完成搜索、组合筛选、选择、详情查看与启动，且两种模式状态同步。
6. 默认不自动选中游戏；筛选排除选中游戏后的行为符合第 4.2 节。
7. 每款游戏使用统一陈列和交互规则，第一款游戏没有任何特殊展示。
8. 详情 URL 可分享、刷新恢复，非法游戏地址和普通非法路由均有明确状态。
9. 可用、维护中、未开放及启动地址异常的游戏具有正确且不可混淆的按钮状态。
10. WebGL 或关键 3D 资源失败时，必要的注册、列表浏览、详情和有效游戏启动仍可使用。
11. 桌面端键盘、焦点、200% 缩放和减少动态效果行为符合本文要求，不以手机端适配作为当前验收条件。
12. 页面没有宣传性文案、虚构数据、破图、空白占位图、虚假在线人数、虚构注册成功或无实际作用的按钮。
