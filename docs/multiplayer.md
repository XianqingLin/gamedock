# GameDock:联机边界

> **跨项目契约（身份凭证/邀请深链/用户资料/postMessage 通道）已于 2026-11-22 抽出至工作区 [../../docs/platform-seam.md](../../docs/platform-seam.md)，两侧以契约为准**；本文件只保留平台侧边界定位。

平台对标 Steam 的"商店/库 + 账号/社交"层,**不提供任何联机服务**:不做大厅、房间、匹配、排位、对战中转、对战凭证、聊天室。每个游戏能不能联机、怎么联机(自建服务器 / P2P)是游戏自己的事,平台不感知也不参与。

平台保留的联机相关能力只有一个:**好友邀请(仅信息传递)**——2026-11-23 落地,2026-11-24 定案「通知 + 接受即自动入房」模型(契约见工作区 platform-seam.md §4,双侧确认):

1. 邀请的发出与展示:发出方在游戏运行页好友面板右键好友「邀请游玩」(携带当前游戏与游戏经 SDK `game:invite-context` 上报的加入参数);接收方全站可见——右下角 Toast(自下滑出、约 6s 后下滑消失、点击打开好友栏并作废剩余 Toast 队列)+ 好友栏对应好友行右侧内联邀请区(文字下接受/拒绝两钮);同邀请者新邀请覆盖旧邀请,邀请 TTL 3 分钟;发现靠全站轻轮询(登录态 10s、后台退避 30s),无推送通道。原「好友列表顶部固定邀请行、打开抽屉才可见」作废。
2. 把人带进游戏:B 点「接受」→ 平台标记 accepted → 运行页未打开则打开 `?invite=` 深链,已在本页同游戏则原地重挂 iframe;游戏落主菜单后凭未过期邀请票**自动入房**(游戏内无任何邀请 UI,原"挂卡点击入房"作废,见 bvn DESIGN §6.4)。params 一次性投递(2026-11-24):首次取参即下发,刷新重取为空——刷新恢复由游戏侧票自持(重进主菜单自动入房),平台重发会复活已销的票。
3. 可验证身份凭证:平台签发短时效"我是用户 X"凭证(对应 Steam `GetAuthSessionTicket`),由游戏或其自有服务器向平台校验端点验证连入者身份;平台不参与连接的建立与传输。**尚未实现**。

对齐点(§3 凭证)见工作区 platform-seam.md;邀请的接口形状已双侧落地。对应 Steam:邀请 ≈ Rich Presence `+connect` 深链;Steam SDR 字节管道中转属可选服务,对应本平台不做的部分(曾经的"方案 A"平台中转架构已于 2026-11-16 作废、2026-11-18 删除残留,需恢复从 git 历史找回)。

## 游戏侧现状（2026-11-23 校准）

- **web-bvn**:对局调度 rollback(bvn DESIGN §6),房间服 = BCC 国内节点 + CF Durable Object 外服节点双节点(操作见工作区 `docs/SERVER-OPS.md`);平台中转"方案 A"残留已删除。**邀请链已落地**(2026-11-23 深链,2026-11-24 收口为邀请票);2026-11-24 随「通知 + 接受即自动入房」模型定案:游戏内邀请 UI(主菜单挂卡)取消,主菜单凭未过期票自动入房、兑票失败一律销票(bvn DESIGN §6.4);剩余 = 身份凭证服务器侧校验与平台昵称/头像资料接入(见 platform-seam.md §3/§5)。

## 与联机无关、继续有效的契约

- 嵌入:iframe + postMessage 信封 v1 `{v, t}`,`platform:`/`game:` 前缀,`connectGameDock()` 握手(standalone 降级)。
- 存档走平台:`sdk.saves.*`,游戏 iframe 不用 localStorage 存档。
- 好友基础关系、账号会话:平台侧继续有效。
