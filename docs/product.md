# GameDock:产品需求

用户可见行为的唯一需求来源。技术约束见[tech.md](./tech.md),联机边界见[multiplayer.md](./multiplayer.md)。

## 1. 定位与范围

GameDock 是网页游戏平台(个人学习项目):游戏库浏览 + 账号 + 好友社交。游戏以独立游戏页面 + 平台外边框运行。**平台层不做联机**:不做大厅、房间、匹配、排位、对战中转、对战凭证、聊天室;唯一例外是好友邀请(仅信息传递,尚未实现,接入时另补需求)。

交付范围:

- 游戏库:探索轮播、封面网格浏览、搜索、排序、专题与分类筛选、详情与启动。
- 账号:用户名密码注册登录、会话保持;个人资料(头像/名称/ID)在好友栏身份区管理。
- 好友(2026-11-23):好友列表固定含内置「测试用户」bot(不可删除、恒在线、发消息自动回复,供单账号自测好友聊天链路);好友间互发文字消息;添加好友按对方用户 ID 搜索、需对方同意;发送/接受/拒绝/取消请求、删除好友;好友邀请(仅信息传递,见 multiplayer.md 与平台接缝契约);好友列表与顶栏自身均展示在线状态(同源心跳判定)。

- 平台存档:按游戏隔离的存档读写,值对平台不透明。
- 游戏托管:静态资源托管在独立内容域,跨源 iframe 运行。

不包含:手机端适配;3D 场景(已移出当前范围,重启另立文档);游戏内部玩法与联机服务器(各游戏自理);支付、广告、评论、积分、成就、排行榜、聊天室;游戏投稿审核流(等真实需求再建,存储布局已预留)。

《死神 VS 火影》重构版仅作为第一款接入的游戏,不享有特殊样式、推荐位或特殊交互。演示数据只用于开发和测试。

## 2. 内容与展示

- **平等展示**:所有游戏统一卡片规格、信息层级与视觉权重;顺序只由数据排序决定,无推荐/热度/付费权重;不可用游戏仅限启动,不限制浏览。
- **文案**:只保留功能性文字;不用"必玩神作"等推荐性措辞,避免商业化、商城化用语;信息只能来自数据,缺失时隐藏整个字段;无真实来源不显示在线人数;错误与空状态只说明状态和可执行操作。
- **视觉**:深色克制、内容为主角;装饰不得比交互目标醒目;不设虚假按钮或空页面入口;不使用侵权或来源不明的美术资源。

## 3. 账号与好友

- **账号与个人资料(2026-11-23 复改)**:注册登录用用户名 + 密码,重复/非法/过短给明确错误;httpOnly Cookie 会话,host-only(不进游戏域);登出清会话;未登录可浏览,好友与存档需登录。**没有独立的个人信息页**——资料三要素收进好友栏身份区:头像点击弹窗切换系统预设(内置 SVG 头像集,点击即保存,可选「默认」恢复首字母头像;测试用户 bot 的专属头像不在可选清单);名称旁编辑钮内联改名,改名即改登录用户名(沿用注册校验与唯一性,保存失败就地报错并停留编辑态);显示「ID:」+ 用户 ID(悬浮/聚焦出复制图标钮一键复制,供他人加好友),不显示自身在线状态。左侧栏为「游戏」「成就墙」「存档」三个同级顶级入口(成就墙为占位页,成就数据源接入后在此渲染;存档页按游戏分组列出存档槽位——键名/大小/更新时间,值对平台不透明,支持删除单条,删除幂等、失败以服务端数据兜底重取,无存档给得体空状态)。顶栏与好友面板、游戏运行页的头像同源(预设头像或首字母回退)。

- **好友(2026-11-23 复改,含聊天/邀请/右键菜单)**:好友列表固定含内置「测试用户」bot(不可删除、恒在线、行侧带「测试」角标;给TA发消息由服务端落一条固定回声式自动回复,不依赖外部 AI 服务,让好友聊天链路在单账号下可自测收发闭环)。**入口(2026-11-23 复改)**:顶栏没有独立的好友按钮,点击右上角用户头像/名称(游客或登录态相同)直接滑出好友抽屉,不使用下拉菜单;抽屉底部提供「退出登录」;游客在抽屉内直接获得「登录/注册」按钮(打开登录/注册对话框),不弹单独提示浮层。抽屉无标题(顶行左侧为当前用户身份——头像(点击换头像)+ 名称(旁有编辑钮)+「ID:」行,右侧为关闭钮;工具独占一行:两条横线之间填充另一种底色的通栏带状区域(左右贴边填满),左侧文字「好友」,右侧三个图标钮(底色与通栏同色、仅显示图标,激活态用图标颜色区分):搜索、好友请求、添加好友;主列表标题移除)。面板内头像尺寸一致(48px),头像与名称+状态之间留有空隙。搜索点击后「好友」文字与搜索钮让位给搜索框(搜索框从中点向左右展开、A 宽度不变,退出叉在框内右侧),好友请求与添加好友两钮保持原位不被顶掉,按用户名过滤好友。好友请求是切换钮而非下拉面板:点击后按钮进入激活态(高亮),主列表由好友列表切换为全部申请——收到的请求为 ✓/✗,已发出的请求为"等待处理"+ ✗ 取消;再次点击退出激活态并切回好友列表;按钮带未处理数徽标;点搜索或添加好友也会退出激活态。添加好友仍以下滑面板呈现(对方用户 ID 输入框 + 发送钮,发送成功后自动切到请求视图)。好友行均展示大圆形头像、名称与在线状态(在线/离线,来源为登录态浏览器每分钟的心跳上报,5 分钟内有心跳视为在线;服务端用统一份 `last_seen_at` 判定,无心跳数据一律离线,不编造在线状态;自身身份区显示 ID 而非状态;面板打开期间每 20 秒轮询刷新在线状态——新邀请的可见性不依赖此轮询,由全站通知轮询承担(见游戏邀请条目))。添加好友通过对方用户 ID(7-8 位数字,注册时分配)搜索,需对方同意:请求/接受/拒绝/取消/删除;重复请求、对自己请求等无效操作明确报错,不产生重复数据。
  - **好友行交互(2026-11-23)**:**双击**(或键盘 Enter/Space)打开聊天框弹窗——单击不触发,避免误触;**右键**(或键盘 Menu/Shift+F10)弹出该好友的操作菜单,点外部/Escape/滚动即关闭(Escape 只关菜单不关抽屉):「发送消息」(打开聊天框)、「邀请游玩」(仅在用户正在游玩某款游戏时提供——即运行页的好友浮层,主站等无游玩上下文的抽屉不显示此项)、「删除好友」(带二次确认弹窗,文案含对方名称与"删除后需要重新添加",取消/删除两钮)。行内不再放常驻「删除」按钮。测试用户 bot 行的菜单只有「发送消息」。
  - **好友间聊天(2026-11-23)**:聊天框加载历史(最多 100 条)并按本端/对方分侧渲染;打开期间每 4 秒轮询拉取新消息(无推送,对方在线与否都能收到);单条 ≤2000 字,失败展示服务端错误文案,不伪造内容;只能与已确认好友聊天(非好友/自己明确报错)。
  - **游戏邀请(2026-11-24 定案「通知 + 接受即自动入房」,仅信息传递)**:在运行页游玩某游戏时,右键好友点「邀请游玩」→ 平台把当前游戏与游戏经 SDK 上报的加入参数(如房间码,平台不解析)存为邀请;发出成功有轻提示,失败报服务端错误;只能邀请已确认好友,测试用户不可被邀请。游戏未上报加入参数时邀请只带游戏本身。**接收侧通知(全站生效,不要求抽屉打开)**:① 右下角矩形 Toast 自下滑出——邀请者头像 + 名称 + "邀请你玩 XX 游戏",停留约 6 秒后下滑消失;**点击 Toast 打开好友栏并作废剩余 Toast 队列**(被作废的邀请只在好友栏可见,好友入口即头像/名称钮带未读角标兜底可见性);Toast 严格单显队列,前一个下滑消失后下一个才登场,同一邀请者的重复邀请只刷新内容与倒计时不重复排队。② 好友栏对应好友行的**右侧内联邀请区**:文字"邀请你玩 XX"在上、接受/拒绝两钮在文字正下方(均落在行右半边,不再有顶部固定邀请行);同一邀请者的多次邀请新覆盖旧。邀请 TTL 3 分钟,过期不出现在通知/列表,操作报"邀请已过期"。**发现机制**:全站轻轮询通知端点(登录态 10 秒、页面不可见退避 30 秒),返回待处理邀请与我发出的邀请的拒绝回执(B 拒绝后 A 获一次性轻提示,前端按邀请 id 去重;接受不回执)。**接受即自动入房**:点「接受」→ 标记 accepted → 该游戏运行页未打开则新窗口打开 `?invite=` 深链;已在运行页游玩同一游戏则原地换 `?invite=` 重挂 iframe(不开新窗口);之后由游戏侧落主菜单自动入房(游戏内无任何邀请 UI)。B 主菜单误操作没进成房不补救,A 再邀请一次即可。

- **存档**:按 slug 隔离,键值由游戏自定义;需登录;未接入 slug 返回明确错误;单值有大小上限。

## 4. 探索、浏览、详情与启动

**导航**:左侧栏提供单个「游戏」入口(指向探索页,即平台游戏内容的根入口);右侧顶栏搜索框右侧提供「探索/浏览」导航,对应同一栏目的两个页面。顶栏搜索框左侧为纯图标返回按钮:层级式返回上一级(详情页的上级是浏览页——后退至历史中最近的浏览页位置并保留筛选,运行页等非上级页面不作为返回目标,历史中无浏览页时直达浏览页);探索、浏览等顶级页面无上级,按钮呈禁用态。

**探索页**(`/`,首页):精选游戏大图轮播,最多 5 个内容(数据不足按实际数量);大图下方横排进度条式指示器,当前项填充高亮,点击切换,自动轮播约 6 秒一轮;悬停或焦点进入时暂停,系统开启"减少动态效果"时不自动轮播。内容只从游戏数据派生,不加推荐性措辞,顺序只由数据排序决定。

**浏览页**(`/browse`):「探索/浏览」导航与搜索框同处右半区顶栏(搜索框居左、导航紧随其后);主区顶部为"显示:" + 排序下拉(全部/最新推出/即将推出/按字母顺序,"全部"即数据顺序);卡片只有封面与游戏名,不提供类型、价格等其他字段;右侧为筛选栏,上方"专题"为单选(含全不选),下方"游戏类型"与"游戏方式"为复选框多选、平铺不折叠(游戏方式由游戏数据的能力声明派生,与详情页共用同一套标签);无页脚底栏。

**搜索、排序与筛选**:搜索只匹配游戏名称,忽略首尾空白与大小写,包含匹配;搜索、专题、分类与游戏方式组合须同时满足;结果顺序稳定,排序只由数据字段驱动("最新推出"=已推出按发布日期新→旧、未推出殿后;"即将推出"=未推出的在前且越接近推出越靠前,已推出的按发布日期新→旧跟随);无结果显示空状态 + "清除筛选"(清空搜索、专题、分类与游戏方式);未知分类/专题/游戏方式/排序按未选处理,避免脏 URL 导致永久空结果;选中游戏被筛掉时清选中、关详情,不自动选中首个结果;全部状态写入 URL,刷新与前进/后退均可恢复。

**详情**:头部为通栏区域——《名称》大标题、评分行(数据含评分时渲染)、书签行(概览/评论/成就),书签向下滚动时吸顶固定在顶栏之下(顶栏换行的窄屏取消吸顶);书签下方分左右两栏:左栏概览依次为媒体轮播(未配置截图时回退为单张封面)、简介、游戏类型与游戏方式两栏(各带标题、条目为胶囊标签,竖线固定在左栏水平中点)、完整介绍,简介与完整介绍不带标题;右栏为封面、可用状态与启动按钮、开发者/发行日期/版本等数据中实际存在的其他信息;评分、简介、完整介绍、开发者等可选字段无数据时不渲染;评论与成就书签暂为占位空状态。URL 可分享、刷新恢复,不存在的 slug 显示未找到;页内不设返回按钮,`Escape` 或顶栏返回按钮退出详情并保留筛选,直接打开详情 URL 时回浏览页;前进后退按历史恢复。

**启动四态**:可用 + 有效地址 → 可点击;未开放 → "未开放"禁用;维护中 → "维护中"禁用;地址缺失或无效 → "暂不可启动"禁用;游戏不存在 → 未找到。启动由用户主动点击,不进空白页;详情页点击「开始游戏」不在当前页跳转,而是新窗口打开运行页,外链同样新窗口打开且仅接受 http(s),均带 `noopener`/`noreferrer`。

**运行页**(`/play/:slug`):详情页「开始游戏」在新窗口打开的独立游戏窗口,不展示左侧栏、不提供返回按钮;平台外边框(标题/好友与账号入口/全屏) + 游戏 iframe,顶栏账号区与主站顶栏一致(头像/名称点击即滑出好友栏)。好友以浮层呈现,游戏逻辑全在 iframe 内。浏览器全屏仅包含游戏运行区域。画面比例固定、不随窗口变化的游戏以信箱式展示:游戏画面按自身宽高比居中,周围留白以该游戏主题色衬托(比例来自游戏上报,未上报时用游戏数据配置兜底);画面自适应任意比例的游戏填满可用区域。游戏与平台跨源(内容域),会话 Cookie 不进游戏域。平台与游戏经 postMessage 窄接口通信:平台下发握手(携带 slug 与登录用户或 null),信封带版本号,消息按 `platform:`/`game:` 前缀区分;登录态确认前不挂 iframe。后续存档、分数、联机凭证都在这条通道扩展。**邀请深链(2026-11-23)**:好友点邀请「进入」打开 `?invite=<id>` 深链时,运行页取回该邀请的加入参数,随握手 `join` 字段交给游戏(平台只透传、不解析);游戏经 `game:invite-context` 上报的当前可加入参数,是好友面板「邀请游玩」随邀请携带的载荷。

## 5. 桌面端与可访问性

- 仅面向桌面浏览器验收;200% 缩放或文字换行后主要控件仍可见可用。
- `Tab`/`Enter`/`Escape` 完整可用;清晰焦点样式、语义化控件、无障碍名称;弹层焦点圈定并在关闭后恢复;文字对比度 ≥4.5:1(大字 3:1);状态不只靠颜色表达;点击目标 ≥44×44 CSS 像素。
- 可选声音(非必做):默认静音、用户主动开启、尊重自动播放限制、低音量克制、失败不影响核心流程。

## 6. 异常与降级

- 身份请求失败不误用旧身份,提供恢复入口。
- 数据为空与搜索无结果是两种状态;前者不提供"清除筛选"。
- 游戏不存在与路由未找到分别有明确状态和返回入口。
- 封面失败用统一的本地默认封面,不破图、不用外链占位。
- 单个资源失败不拖垮应用;游戏内容域加载失败只影响游戏区,不影响平台页面。

## 7. 验收标准

1. 注册、登录、登出、会话保持可用,好友栏身份区可换头像/改名/复制 ID;无效凭据与重复注册被明确拒绝。
2. 好友全流程正确:测试用户 bot 固定在列表、可聊天且自动回复;好友间聊天(轮询收发、非好友拒绝);右键菜单三操作与删除二次确认;按 ID 搜索添加并需对方同意,在线状态来自真实心跳,无效操作明确报错且不产生重复数据;游戏邀请仅信息传递——发送限好友与已接入游戏,接收侧通知与队列行为符合游戏邀请条目(Toast 单显队列/点击作废并开好友栏/角标、行内右侧邀请区、同邀请者覆盖、TTL 过期拒绝、接受即自动打开或原地重挂),深链参数经握手透传。

3. 存档按用户与 slug 隔离,写读列删正确,未接入 slug 明确报错。
4. 搜索、排序、专题与分类筛选、选择、详情、启动全流程可用;默认不自动选中;筛掉选中项的行为符合第 4 节。
5. 所有游戏展示与交互规则统一,第一款游戏无特殊展示。
6. 详情 URL 可分享、刷新恢复;非法游戏地址与非法路由有明确状态。
7. 启动四态正确且不可混淆;不产生空白路由或空白窗口。
8. 游戏在跨源 iframe 运行,握手携带 slug 与登录用户;外边框返回与全屏可用。
